## Matroska support (in progress)
- [x] P0 — MKV import correctness. Audit confirmed `MediaSource::probe()` already copies `AVCodecParameters::extradata` for video/audio/subtitle and `Demuxer::open()` routes through it, so **no production-code change was needed**. Added transmuxed MKV fixtures (`test_video.mkv`, `test_av.mkv` via `ffmpeg -c copy -f matroska` in `tests/CMakeLists.txt`) and regression tests covering: MKV video/audio extradata preserved, container name reported, `Demuxer` info carries extradata, packets + keyframes readable, and first-frame thumbnail decode from an MKV source (proves extradata reaches the h264 decoder). Also added the missing `add_dependencies(bl_core_tests bl_media_fixtures)` so the POST_BUILD fixture copy cannot race the generator — **573/573 green** (debug + release)
- [x] P1 — Encoder extradata plumbing. **Root cause found was not just the missing query**: libx264 only fills `AVCodecContext::extradata` under `AV_CODEC_FLAG_GLOBAL_HEADER`; MP4 export worked before only because `movenc` re-extracts SPS/PPS in-band from the first keyframe, which `matroskaenc` does not do. So: bumped the plugin ABI to **v3** and added a trailing optional `get_extradata` vtable entry (NULL for plugins that do not implement it — passthrough and the test fixtures stay untouched); added `BlCodecConfig::enc_flags` with `BL_ENCFLAG_GLOBAL_HEADER` so the host opts the encoder into publishing parameter sets out-of-band; `ffmpeg_plugin_get_extradata()` captures a private copy after `avcodec_open2` and again after the first received packet, freed in `cleanup()`; all nine FFmpeg codec plugins wired up; `ExportEngine` caches per-stream copies (`videoExtradata()`/`audioExtradata()`, refreshed after each successful packet, cleared in `cleanup()`) and passes them to `Muxer::setVideoExtradata`/`setAudioExtradata`, which attach an `av_mallocz` copy to `AVCodecParameters` before `avformat_write_header`. Verified end to end: MP4 output still carries a correct 46-byte `avc1` configuration record, and a Matroska file written through the same path now has a non-empty `CodecPrivate` (`ExportEngineExtradata.MatroskaTrackCarriesCodecPrivate`). 13 new tests (7 plugin-side, 6 host-side) — **586/586 green** (debug + release); tsan unchanged at its pre-existing 22 failures
