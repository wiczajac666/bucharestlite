  - **CI then exposed two Windows-only test bugs that had always been passing by luck.** `ProjectRepositoryTest.RoundTripPreservesEverything` and `ProjectController.saveAndOpenRoundTripPreservesDocument` both feed a **root-relative** media path (`/absolutely/elsewhere/broll.mp4`, `/media/clip.mp4`) and asserted it against `fs::absolute(...)`. On Windows a root-relative path is not `is_absolute()`, so `resolveMediaPath` joins it onto the **project dir** and keeps that dir's drive; `fs::absolute` instead resolves against the **process CWD**. The two agree only when the temp dir and the working directory share a drive — true on the release VM (both `C:`), false on the runner (`%TEMP%` on `C:`, checkout on `D:`), where the tests failed `C:` vs `D:`. The product behavior was correct in both places; the expectations were the defect, and now derive from the project dir (which yields the right answer on Windows *and* POSIX, since an absolute right-hand path wins outright). Worth remembering: these two only ever validated the round trip when the build tree and temp dir shared a volume, so a passing Windows run previously proved less than it appeared to.
